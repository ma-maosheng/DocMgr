# 资料室管理系统 — 覆盖安装与备份

程序版本见登录窗左侧、主窗口导航栏底部。发版只改程序文件，**不要改坏 SQL Server 里的业务库连接或误删库**。

## 数据库在哪

业务数据在 **SQL Server** 中，默认库名 `DocMgr`。

- 连接串：安装目录 `appsettings.json` → `Database:ConnectionString`。  
  示例（本机）：`Server=localhost;Database=DocMgr;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true`
- 局域网共用一台库服务器时：各终端 `appsettings.json` 指向同一 `Server=…;Database=DocMgr;…`（示例见 `appsettings.lan.example.json`）。
- 帮助页 / 高级数据管理页会显示当前目标，形如 `服务器\实例 / 库名`。本机与远程仅表示连接对象，数据都在 SQL Server 里。

> 旧版曾使用程序目录下的 `DocMgr.db`（SQLite）。当前版本已改为 SQL Server，**不要再按 `.db` 文件方式拷库或覆盖**。

## 覆盖安装（升级）步骤

1. 让所有终端退出本程序。
2. 在「系统设置 → 高级数据管理」点 **备份当前库**，把生成的 `.bak` 存到安装目录以外（U 盘、文档文件夹或服务器备份盘）。  
   - 备份为 SQL Server 标准备份文件（`BACKUP DATABASE … WITH COPY_ONLY`）。  
   - 保存路径须 **SQL Server 服务能写入**；远程实例时勿选仅本机可见、服务端读不到的路径。
3. **只替换** `DocMgr.exe`、依赖 dll、以及需要更新的配置模板。  
   **不要**用新包里的空配置直接覆盖已改好的 `appsettings.json`（会丢服务器名/库名）。  
   推荐用仓库脚本（在 `DocMgr` 目录执行），避免手工整夹覆盖：

   ```text
   powershell -NoProfile -File tools\PublishOverlay.ps1 -TargetDir "D:\DocMgr"
   ```

   目标电脑没有 .NET 8 桌面运行时时加上 `-SelfContained`。脚本若目标已有 `appsettings.json` 则保留，并把新模板写成 `appsettings.json.published`。
4. 启动新版本。若有数据库结构升级，程序会执行 `Database.Migrate()` 升级当前 SQL Server 库（不会清空业务数据）。
5. 登录确认待办与业务数据仍在。

## 不要这样做

- 把整个安装文件夹覆盖后，用新包里的 `appsettings.json` 冲掉现网连接串（连错库或连不上）。
- 升级过程中其他电脑仍开着客户端写同一 SQL Server 库。
- 在 SQL Server 管理工具里误删 `DocMgr` 库或还原错实例。
- 仍按旧习惯去拷/覆盖 `DocMgr.db`、`DocMgr.db-wal`（当前版本不再使用）。

## 备份与还原

### 程序内（推荐）

| 操作 | 谁可做 | 说明 |
| --- | --- | --- |
| 备份当前库 | 资料管理员、系统管理员 | 生成标准 `.bak`，建议存安装目录以外 |
| 从备份还原 | 仅系统管理员 | `RESTORE … WITH REPLACE` 整库覆盖；完成后程序退出，须重开 |

远程 SQL Server 还原前必须所有终端已退出。还原不可撤销，操作前请再备一份当前库。

### 用 SSMS / T-SQL（可选）

同一 SQL Server 实例上可对 `.bak` 手工还原，例如（库名以实际为准）：

```sql
ALTER DATABASE [DocMgr] SET SINGLE_USER WITH ROLLBACK IMMEDIATE;
RESTORE DATABASE [DocMgr] FROM DISK = N'D:\备份\DocMgr-backup-xxxx.bak' WITH REPLACE;
ALTER DATABASE [DocMgr] SET MULTI_USER;
```

## 配置

- 新版本若带了新的 `appsettings.json`，不要直接覆盖已改过连接串的那份；只把需要的新项手工合并进去。脚本已保留现有文件时，可对照 `appsettings.json.published`。
- 换库服务器时：改 `Database:ConnectionString` 后重启程序；并确认目标实例上已有（或可自动迁移创建）`DocMgr` 库。

## 测试机安装包（自包含 zip）

目标电脑未装 .NET 8 桌面运行时时，在仓库 `DocMgr` 目录执行：

```text
powershell -NoProfile -File tools\PackTestInstaller.ps1
```

生成 `installer-out\DocMgr-Setup-*-win-x64.zip`（已含运行时）。测试机解压后可直接运行 `DocMgr.exe`，或运行 `Install-DocMgr.ps1` 安装到 `%LOCALAPPDATA%\DocMgr`。说明见包内 `README-install.txt`。

已有 `publish\overlay-win-x64` 时加 `-SkipPublish` 只重新打包。

> 测试机仍须本机或网络可达的 SQL Server，并在 `appsettings.json` 中配置正确连接串。

## 可选：Inno 安装包

本机安装 [Inno Setup 6](https://jrsoftware.org/isinfo.php) 后，在仓库 `DocMgr` 目录执行：

```text
powershell -NoProfile -File tools\Build-InnoInstaller.ps1
```

会框架依赖发布、下载并附带「.NET 8 桌面运行时」安装包、再编译 `tools/DocMgr.iss`，输出到 `installer-out\DocMgr-Setup-*.exe`。安装时若本机没有该运行时，向导会提示是否安装包内 `redist`；安装结束页会说明 `appsettings.json` 与 `appsettings.lan.example.json` 的用法。生成的安装程序不会替换已有 `appsettings.json`。向导默认目录为当前用户下的 `DocMgr`，可改成 `D:\DocMgr`。
